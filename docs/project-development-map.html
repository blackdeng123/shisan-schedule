开发路径

按“系统怎么长出来”的顺序组织，而不是按日期流水账组织。每一步都对应当前仓库中的模块或文档。

1. 工程骨架

Kotlin 2.0.21、AGP 8.13.2、Compose、Material 3、多模块 Gradle，先建立 app、core、feature 的边界。

2. 领域模型

沉淀 Schedule、Course、Grade、Exam、AuthState、SyncResult，并用 @Stable 约束 Compose 重组。

3. 本地数据

Room 承担课表、课程、节次、成绩、考试的本地源；DataStore 保存活跃课表、会话标记、上次同步时间；Security Crypto 保存凭据。

4. 教务接入

Ktor + OkHttp 维持 Cookie，支持门户统一认证和 JWXT 直登，登录后抓取 HTML 页面并由 Jsoup 解析。

5. 同步编排

启动自动同步、12 小时 TTL、按需同步、防重复请求、会话过期重试、失败原因映射逐步补齐。

6. 功能页面

登录、课表周视图、课程编辑、课表设置、上课时间、成绩、考试、我的、设置页形成主要移动端路径。

7. 体验优化

TextField 轻量化、页面转场、同步解析切到 Default 线程、R8、Baseline Profile、同步按钮并发锁。

8. 下一步补齐

通知提醒闭环、深色模式持久化、背景选择、导入能力、多学期同步、统计分析和权限引导。

Room 表结构

表 用途 关键字段
schedules 课表聚合根和显示设置 id, name, startDate, totalWeeks, termId, showWeekend, backgroundUri
courses 课程实例，区分手动和 JWXT 来源 scheduleId, day, startSlot, weeksCsv, source, jwxtKey
class_time_slots 每个课表自己的节次时间 scheduleId, slotIndex, startTime, endTime
grades 成绩缓存 name, credits, score, scoreText, gpa, semester
exams 考试安排缓存 name, location, date, daysLeft, source

数据保存位置

数据 保存位置 读写边界 注意点
账号密码与登录模式 EncryptedCredentialsStore JwxtSession 通过 CredentialsProvider 访问 退出登录会清理凭据和会话标记。
活跃课表 ID UserPreferencesDataSource.activeScheduleId RoomScheduleRepository 删除活跃课表后会尝试选中下一张课表。
上次全量同步时间 UserPreferencesDataSource.lastFullSyncAtMillis StartupSyncCoordinator 仅全量同步全部成功时写入。
课表、课程、成绩、考试 campus.db Repository 暴露 Flow 给 ViewModel 成绩整表替换；考试只清 JWXT 来源；课表按 schedule 替换课程。
